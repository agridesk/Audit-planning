4. NON-RECURRING LIFECYCLE RULE

Lifecycle semantics are owned exclusively by Config_Scopes.Recurring.

For Recurring=NO:
- no certificate birthday is invented;
- no certificate expiry is invented;
- no automatic successor is created;
- Cycle_Key identifies the annual/explicit operational obligation;
- a new year means a new obligation, never mutation of the prior Cycle_Key;
- when both canonical Planning_Window_From and Planning_Window_To are blank and Cycle_Key is a valid four-digit year, the effective operational planning window is YYYY-01-01 through YYYY-12-31;
- this fallback is operational only and creates no certificate semantics;
- a partial explicit window is invalid and hard-blocks planning.

For all linked obligations in a visit:
- the feasible visit window is the intersection;
- an empty intersection is a hard planning block;
- there is no union fallback for planning.

12. NON-BLOCKING FOLLOW-UP DEBT

The following items are not release blockers for AMS-01.6 but remain suitable later cleanup/hardening work:

- Remove the obsolete duplicate legacy implementation of _mp_getCurrentCycleYearFromAuditRow_ from Toolkit_Eligibility.js so only the explicit Model C cycle owner defines that public global. Runtime ownership is already proven correct; this is source hygiene/load-order hardening.
- Continue reducing compatibility dependence on Audit planning AS/AT where consumers can read Model C directly. Audit planning itself remains part of the system as operational/compatibility projection and is not to be dismantled.
- Review compatibility projection behavior for non-recurring blank stored windows; the canonical runtime fallback is already correct and must remain the owner.
- Future manual/bulk creation of Recurring=NO annual obligations must require an explicit Cycle_Key and must never infer certificate expiry.
- 2027 ECAS processing must create new 2027 obligations; 2026 obligations must never be mutated into 2027.
- Clean the harmless materializer schema-name typo fallback Audit_ObligATIONS when a safe source-only cleanup window is available.

These are follow-up engineering hygiene items, not evidence of a failed Model C migration.
