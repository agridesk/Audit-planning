3. IMPORTANT CURRENT MISMATCHES

A. Generic Comments is obsolete as target semantics
Current editor exposes one field named Comments and CompanyUpdateProposalsBackend.js maps it to Companies!Comments.
V2.8 requires:
- existing Comments -> General comments;
- new separate Auditor comments.
Therefore this control must be split before Company editor 2.0 cutover.

B. Contact data currently goes through Manager proposal
V2.8 says contact data is direct Auditor update with audit trail.
Do not reproduce the proposal requirement in 2.0.

C. Planning limitations days/hours currently go through Manager proposal
V2.8 says these are direct Auditor updates with audit trail.
Do not reproduce the proposal requirement in 2.0.

D. Locations correctly belong to Manager governance direction
Keep review/approval, but write through Companies/Locations_JSON canonical owner only.

E. Region is absent from current Auditor Company editor proposal surface
V2.8 makes Region Manager-governed. If Auditor may propose a Region correction in 2.0, it should enter the same governed review queue.

F. Preferred audit months client/backend contract needs attention
The current AuditorCompanyUpdateDialogClient.js reads/collects Preferred audit months and can emit planning/preferredAuditMonths.
The inspected CompanyUpdateProposalsBackend.js does not expose Preferred audit months in companyUpdate_getCompanySnapshot and its visible field-application branches only support planning days/hours, principal contact/comments and locations.
CompaniesBackend.js does support canonical Preferred_Audit_Months directly.
Conclusion: before relying on this feature for 2.0, verify/fix the proposal/backend contract or replace it with the final 2.0 ownership path. Do not assume the current proposal route persists Preferred audit months correctly.

4. 2.0 EDITOR TARGET UI
The Company editor should present fields in three clear categories without exposing the governance mechanics more than necessary:

Operational data — save directly
- Contactperson
- Contact e-mail
- Contact phone
- Planning limitations days
- Planning limitations hours
- Auditor comments

Company preference
- Preferred audit months
- save/review behavior according to final ownership decision

Structural / governed data — submit for Manager review
- General comments
- Region
- Locations

The user should be able to press one Save/Submit action. Server-side routing decides which fields save directly and which become Manager proposals.

5. SERVER-SIDE REQUIREMENTS
- Field ownership enforced server-side, never only by UI visibility.
- One Companies SSoT.
- Direct changes record old value, new value, actor, timestamp and source.
- Governed changes create proposal records and do not mutate Companies until Manager decision.
- Mixed direct + governed changes in one submission may produce different per-field outcomes.
- Return one consolidated result to the Auditor.
- Invalidate only relevant Companies/planning/company-map caches.

6. 3S + VALUE
Speed
- one snapshot load;
- one bundled save;
- no per-field RPC loop.

Scalability
- direct fields do not create unnecessary proposal-queue volume;
- proposal queue contains governance work only.

Stability
- server owns field authorization;
- no generic Comments ambiguity;
- canonical Companies writer/invalidation reused;
- no second Company data store.

Value
- routine data corrections no longer wait on Manager;
- Manager focuses on structural changes;
- planning preferences/limitations remain useful and current.
