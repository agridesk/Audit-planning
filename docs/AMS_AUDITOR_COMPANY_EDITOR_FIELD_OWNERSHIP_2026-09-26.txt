2. V2.8 TARGET OWNERSHIP

DIRECT AUDITOR UPDATE + AUDIT TRAIL
- Contactperson
- Contact e-mail
- Contact phone

- Planning limitations: Hours

MANAGER-GOVERNED / REVIEW REQUIRED
- General comments
- Region
- Structural locations, including location name/GPS/location comment and active location structure
- Preferred_Audit_Months

DECISION — 2026-09-26
Preferred_Audit_Months is Manager-controlled.
- Auditor may propose Preferred audit months in the Company tab.
- Auditor proposal does NOT directly mutate Companies.Preferred_Audit_Months.
- Manager reviews and decides Accept / Reject / Adjust.
- Only after Manager acceptance/adjustment is the canonical Companies value changed.
- All planning surfaces continue to consume the single canonical Companies.Preferred_Audit_Months value.

3. IMPORTANT CURRENT MISMATCHES

A. Generic Comments is obsolete as target semantics
Current editor exposes one field named Comments and CompanyUpdateProposalsBackend.js maps it to Companies!Comments.
V2.8 requires:
- existing Comments -> General comments;
- new separate Auditor comments.
Therefore this control must be split before Company editor 2.0 cutover.

B. Contact data currently goes through Manager proposal
V2.8 says contact data is direct Auditor update with audit trail.
Do not reproduce the proposal requirement in 2.0.

C. Planning limitations days/hours currently go through Manager proposal
V2.8 says these are direct Auditor updates with audit trail.
Do not reproduce the proposal requirement in 2.0.

D. Locations correctly belong to Manager governance direction
Keep review/approval, but write through Companies/Locations_JSON canonical owner only.

E. Region is absent from current Auditor Company editor proposal surface
V2.8 makes Region Manager-governed. If Auditor proposes a Region correction in 2.0, it enters the same governed review queue.

F. Preferred audit months proposal/backend contract must be completed
The current AuditorCompanyUpdateDialogClient.js reads/collects Preferred audit months and can emit planning/preferredAuditMonths.
The inspected CompanyUpdateProposalsBackend.js does not currently expose Preferred audit months in companyUpdate_getCompanySnapshot and its visible field-application branches only support planning days/hours, principal contact/comments and locations.
CompaniesBackend.js does support canonical Preferred_Audit_Months directly.

Target:
- Auditor Company tab continues to expose Preferred audit months as a proposed value.
- Proposal backend must explicitly support planning/preferredAuditMonths.
- Manager review must support Accept / Reject / Adjust for this field.
- Accepted/adjusted value writes to canonical Companies.Preferred_Audit_Months through the canonical Company owner/writer pattern.
- Proposal records retain old value, proposed value, decision, processed-by and timestamp.
- No direct Auditor write to Preferred_Audit_Months.

4. 2.0 EDITOR TARGET UI
The Company editor should present fields in two behavioral categories while allowing one Save/Submit action.

Operational data — save directly
- Contactperson
- Contact e-mail
- Contact phone
- Planning limitations days
- Planning limitations hours
- Auditor comments

Manager-governed — submit as proposal
- Preferred audit months
- General comments
- Region
- Locations

The Auditor does not need separate save buttons. Server-side routing determines which fields save directly and which create Manager proposals.

Preferred audit months UX:
- current canonical months are shown;
- Auditor selects proposed months in the Company tab;
- submission creates a Manager-reviewed proposal;
- until Manager decision, planning keeps using the current canonical value;
- after Manager acceptance/adjustment, all planning surfaces see the new canonical value.

5. SERVER-SIDE REQUIREMENTS
- Field ownership enforced server-side, never only by UI visibility.
- One Companies SSoT.
- Direct changes record old value, new value, actor, timestamp and source.
- Governed changes create proposal records and do not mutate Companies until Manager decision.
- Preferred_Audit_Months is explicitly governed and can never be direct-written by Auditor flow.
- Mixed direct + governed changes in one submission may produce different per-field outcomes.
- Return one consolidated result to the Auditor.
- Invalidate only relevant Companies/planning/company-map caches after an accepted Manager change.

6. 3S + VALUE
Speed
- one snapshot load;
- one bundled save;
- no per-field RPC loop;
- no synchronous Manager review in Auditor flow.

Scalability
- direct fields do not create unnecessary proposal-queue volume;
- proposal queue contains governance work only;
- Preferred audit months creates one governed proposal item, not a second planning preference store.

Stability
- server owns field authorization;
- no generic Comments ambiguity;
- canonical Companies writer/invalidation reused;
- no second Company data store;
- planning never consumes unapproved proposed months.

Value
- Auditor can signal realistic customer month preferences during normal Company maintenance;
- Manager remains final decision owner;
- planning intelligence gets only approved canonical preferences.
