1. Probleem
Auditor Accept duurde circa 13.149 ms (trace cr1793194724082), grotendeels via de oude GAS-route. Gewenst: minder dan 2.000 ms. De bestaande Cloud Run directe Sheets-route was wel geïmplementeerd, maar niet actief.

De service kreeg revisie ams-transport-proof-03337-rw2. De flags zijn cutover-attestaties; bij volgende wijzigingen moet de feitelijke exclusiviteit van alle relevante writers opnieuw worden getoetst. Niet blind kopiëren naar andere omgevingen.

3. Eerste live fout na activering
De snelle route werd daadwerkelijk bereikt, maar faalde met:
DIRECT_ACCEPT_LIFECYCLE_HEADER_MISSING_Last auditor decision
Dit kwam uit cloudrun/transport-proof/auditor-accept-direct-sheets-20.mjs. De oorspronkelijke code zocht de header met exacte tekstvergelijking. Een afwijking in hoofdletters of witruimte kon daardoor een bestaande kolom als ontbrekend behandelen.

4. Correctie
GitHub dev commit b047e0777ba5375815f9d0215fd6dc3bc5c4abe6.
Bestand: cloudrun/transport-proof/auditor-accept-direct-sheets-20.mjs.
De lifecycle-headerlookup normaliseert witruimte en hoofdletters, eist precies één overeenkomende kolom en weigert een write bij ontbrekende of ambigue headers. Er worden geen kolomnummers gegokt. De bestaande directe Sheets batchUpdate schrijft alleen de vijf relevante auditcellen en voegt een audittrail-queue-item toe in dezelfde batch.

6. Belangrijke beperkingen / nog te verifiëren
De gebruiker heeft de succesvolle timing bevestigd. Een afzonderlijke, expliciete controle van de uiteindelijke Accepted-status, audittrail-queueverwerking en operationele notificaties is in dit incidentverslag niet gedocumenteerd; deze mogen niet zonder bewijs als afgerond worden aangemerkt.
De Sheets API batchUpdate is atomair als request, maar biedt geen conditionele compare-and-swap op de eerder gelezen bronrevisie. De Firestore-lock in Cloud Run is niet automatisch gedeeld met GAS LockService. Daarom zijn exclusief eigenaarschap en afscherming van concurrerende lifecycle-writers essentieel. Bij uitbreiding van Manager/Auditor lifecycle-schrijfpaden opnieuw controleren.
Deze oplossing is uitsluitend voor DEV gevalideerd; geen PROD-goedkeuring of SWAP-wijziging afleiden.

7. Ontwikkelregels
- Begin bij het daadwerkelijke gebruikerspad en de trace: GAS versus directe Cloud Run-route.
- Verifieer cutover-eigenaarschap en exclusiviteit vóór activering van directe writes.
- Gebruik canonieke headers, normaliseer onschuldige tekstverschillen en fail closed bij ontbrekende/dubbele kolommen.
- Test gericht, deploy alleen DEV, en meet vervolgens een echte Accept; source-tests bewijzen geen live latency.
- Bevestig status, audittrail en notificatie apart.
- Geen oude AMS-roadmaps V2.7 of eerder als actuele bron gebruiken.
- Houd GitHub Actions-kosten laag: bundel wijzigingen en vermijd onnodige CI-runs.
