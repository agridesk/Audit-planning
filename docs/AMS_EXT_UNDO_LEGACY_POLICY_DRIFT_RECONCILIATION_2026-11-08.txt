Date: 2026-11-08
Scope: isolated DEV model C direct writer only (ams-fase12-dev); PROD untouched
Owner: cloudrun/transport-proof/model-c-extension-dev-direct-20.mjs

RCA
Historic DEV EXT Undo events written by CLOUD_RUN_DIRECT_MANAGER_EXTENSION may leave Extension_Metadata_JSON with undo:true and prior policy-derived Planning_Window dates. If Config_Scopes changes (e.g. GRASP Planning to -1 to -2), requiring exact equality with the current Config_Scopes window permanently blocks a legitimate subsequent EXT. An existing MPS-GAP extension on the same audit is independent.

CONTROLLED BEHAVIOUR
- Require ACTIVE canonical Audit_Visit_Obligations linkage, current Pending Planning audit, non-ECAS obligation, valid current scope EXT policy and verified source identity/Manager role/DEV isolation.
- For old metadata, require exact legacy source, undo:true, positive bounded historical EXT duration (1-24 months), Extension_Applied false and effective expiry equal base expiry.
- Historical pre-expiry planning window must be valid, month-aligned relative to base expiry, within -24..0 months, at most 12 months wide; arbitrary dates are not treated as a verified historical policy.
- On Apply, use CURRENT Config_Scopes duration and planning window. Preserve the legacy metadata and old window as priorLegacyUndoMetadata/priorLegacyUndoWindow for provenance.
- The new transaction's Undo preimage is the CURRENT canonical unextended policy window. After Undo, future EXT can be applied normally; no repeated stale legacy condition.
- No automatic mother/daughter propagation; only the selected obligation changes. Manager grid aggregate is recalculated from active linked obligations; verify effective expiry and readback.
- Never bulk-migrate, overwrite user data automatically, infer extension from grid state, or disable writer fencing.
