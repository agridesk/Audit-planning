P0 CUTOVER PARITY

1. Canonical lifecycle/write owner
Status: FOUNDATION PRESENT
2.0 save delegates to GAS canonical planning writer. Cloud Run must not duplicate lifecycle transitions.

2. Canonical availability semantics
Status: IMPLEMENTED IN FOCUSED UI; ACCEPTANCE PENDING
Required parity:
- missing day row = available;
- explicit available = available;
- recurring/default blocked weekday/weekend = soft/advisory;
- manual hard-unavailable = hard block;
- committed/provisional audit occupancy = hard interval;
- multiple non-overlapping audits per day allowed;
- overlap hard-blocked;
- 09:00-17:00 full coverage OR >=8h occupancy inside 08:00-18:00 = fully occupied;
- partial audit occupancy leaves remaining hours planable.
Current R57 implements visual separation of soft warning versus audit occupancy. Validation must use the same resolved semantics.

3. Planning window
Status: IMPLEMENTED IN FOCUSED UI; ACCEPTANCE PENDING
Hard date guard exists and UI uses effective usable window from max(current date, canonical planning-window start) through canonical planning-window end.

4. Required/planned hours
Status: IMPLEMENTED IN FOCUSED UI; ACCEPTANCE PENDING
Required / Planned / Remaining summary is present.

5. Multi-slot planning
Status: FOUNDATION PRESENT
Multiple blocks supported; no arbitrary five-slot business ceiling.
Still required: clearer selected-slot list/editor parity and per-slot removal/editing.

6. Execution locations
Status: PARTIAL
Canonical Companies.Locations_JSON is read; inactive locations are excluded and code/name/GPS/comment are projected into focused context.
Still required:
- stronger read-only location registry/map presentation where useful;
- derive/report planned hours by execution location from slots; no duplicate manual hours field.

7. Auditor selection / preassignment
Status: PARTIAL
Qualification filter and preassignment preference exist.
Still required:

8. Company planning context
Status: SUBSTANTIALLY PRESENT; ACCEPTANCE PENDING

Still required parity from 1.0:
- improve presentation/legibility without changing semantics.

9. Preferred audit months
Status: PARTIAL
Canonical value displayed.

10. Calendar navigation / usability
Status: IMPLEMENTED IN FOCUSED UI; ACCEPTANCE PENDING

13. 3S / performance
