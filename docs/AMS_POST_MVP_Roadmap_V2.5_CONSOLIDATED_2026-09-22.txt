4. P0/P1 — CONTROLLED RE-ADJUST / PLANNED-AUDIT MODIFICATION
4.1 Controlled Reschedule action
Do NOT expose unrestricted generic “edit audit”.
Primary changes:
- date;
- time;
- blocks;
- auditor where explicitly supported;
- execution location;
- scopes only under explicit lifecycle rules.
Lifecycle:
- Pending Planning: normal edit.
- Pending Approval: rerun validators and approval flow.
- Approved: do not silently preserve approval if changed facts invalidate it.
- Accepted: planning-impacting change requires renewed auditor acceptance; current direction Accepted -> Approved.
- auditor change = distinct high-impact action.
Transactional handling:
- old Availability release;
- new Availability block;
- qualification;
- rotation;
- planning window;
- workload;
- status;
- notification;
- audit trail;
- revision/concurrency.

4.2 Scope-aware Re-adjust
- operate through Company_Scopes / Audit_Obligations;
- respect dependencies;
- preserve history;
- recompute visit window;
- never mutate prior annual obligation into a new cycle.

6.2 Multi-location audits

6.3 Travel mode awareness
