BUG-001 — Auditor Plan must require Self planning = Yes
Status: DEPLOYED TO DEV 2026-10-10 — ACCEPTANCE PENDING
Commits: 6686f575, 697c341d, 3f1ab4f3, 28aca2d5, ea2e2477
Priority: HIGH
Area: Shared Audit Grid 2.0 / actor capabilities
Finding:
An Auditor can currently receive a Plan action for a Pending Planning audit because the audit is preassigned to that Auditor, even when Allow self planning = No.
Required behavior:
- Auditor Plan is available only when Allow self planning = Yes.
- Preassignment alone does not grant self-planning permission.
- Hard eligibility remains required.
- Manager planning remains unaffected.

BUG-002 — Auditor visibility after assignment must follow Assigned to
Status: DEPLOYED TO DEV 2026-10-10 — ACCEPTANCE PENDING
Commits: 6686f575, 697c341d, 28aca2d5, ea2e2477
Priority: HIGH
Area: Shared Audit Grid 2.0 / actor scope
Example: TEST_Completed Eta visible to Paco Pelota while Assigned to Isália.
Likely cause:
Preassigned Auditor is still used as an ownership/visibility signal after the audit has moved beyond initial Pending Planning.
Required behavior:
- Preassignment is relevant only before actual assignment/planning.
- Once an audit is assigned/planned, Auditor visibility follows current Assigned to.
- Historical Preassigned Auditor must not leak another Auditor's audit into their portal.

BUG-003 — New assignment/preassignment must prevent non-qualified Auditor
Priority: HIGH
Area: assignment validation
Required behavior:
- Every mutation path that assigns or preassigns an Auditor must use the central hard qualification validator.
- Existing historical assignments may remain when qualification is lost later; these require an alert, not retroactive rewriting.
- Existing red alert for current qualification conflict remains defense-in-depth.
Implementation update 2026-10-10:
- Planning commit routes already use central V2.11 hard qualification validation.
- Scope Manager preassignment mutation now fails closed through `_mp_assertAuditorQualifiedForPlanning_` before Model C scope-owner commit.
- Selected scopes are projected into the qualification check before mutation so qualification is checked against the requested new scope set, not stale row state.
- Regression contract added. DEV deployment pending green npm test.

PERF-001 — ACTION SPEED / 3S
Status: ACTIVE ACCEPTANCE CRITERION
- User reconfirmed 2026-10-10 that action speed is important.
- Complete, Cancel, Reject, Approve, Accept and similar grid actions should remain direct, bounded and micro-refresh based.
- Avoid full-browser refreshes, unnecessary GAS roundtrips, N+1 reads and synchronous non-critical side effects on the hot path.
- Treat noticeable latency regressions as defects even when the action is functionally correct.

PERF ACCEPTANCE MEASUREMENTS — 2026-10-10
- ACCEPT: 2863 ms total (Cloud Run 2782; read 1757; write 259; queue 684).
- COMPLETE: 2506 ms total (Cloud Run 2409; read 588; write 1126; delete 442; queue 237; availability rows 2; patch 2).
- Extension Apply: 4551 ms — exceeds 3S target and is a performance defect.
- Extension Undo: 1181 ms — acceptable.
- Priority: investigate Extension Apply hot path first; then ACCEPT read latency and COMPLETE write/delete latency.

PERF ACCEPTANCE RECHECK — 2026-10-10

- Current status: accepted for continued development; retain PERF-001 as regression guard. Do not allow these action times to drift upward unnoticed.
